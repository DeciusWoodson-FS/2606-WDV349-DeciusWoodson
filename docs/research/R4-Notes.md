## Sub-Topic 1 - Thinking in React

Research here was conducted on the React, and the mental model a dev should take when approaching this technology.

# Key findings:

- Breaking UI into a component hierarchy is the first step in React development. Drawing the boxes around your mockup into distinct components is crucial, and using the "single responsibilty principle" will help in understanding what each component does on it's own.

- Build static first, add state last. Rather than initially worrying about interactivity, building a static version of the application with mock data aids in knowing where things are supposed to be and how they should show up. Once that much is done, then you can worry about adding state to handle minimal data like a search query for example.

## Sub-Topic 2 - File Structure in Development

Research here was conducted on file structure, organization, configuration, and documentation within a project.

# Key findings:

- The best practice is to keep the file structure clear, consistent, and scalable. While there is no true "perfect" layout, it should at least be accessible and easy to navigate for future maintainers, or people who just want to check out your work. This sets a strong foundation for collabrative development.
